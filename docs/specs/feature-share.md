### 프로젝트 목적

기존에는 약속 장소를 정할 때 카카오톡, 지도 앱, 캘린더 등을 따로 사용해야 한다.

어디가까는 약속 정보를 하나의 약속방 안에서 구조화하여, 장소 결정부터 도착 상황 확인까지의 흐름을 편리하게 관리하는 것을 목표로 한다.

## 2. 배경 및 문제 정의

### 문제

약속을 잡는 과정에서는 다음과 같은 불편함이 발생한다.

- 장소 후보가 채팅방에 흩어져 다시 찾기 어렵다.
- 여러 장소를 지도 위에서 한 번에 비교하기 어렵다.
- 투표 결과와 실제 장소 정보가 연결되어 있지 않다.
- 확정 장소와 약속 시간이 대화 속에 묻히기 쉽다.
- 약속 당일에는 “어디야?”라고 반복해서 확인해야 한다.
- 장소 검색, 의견 조율, 길찾기, 일정 등록이 여러 서비스에 분리되어 있다.

### 기존 도구의 한계

| 기존 도구             | 한계                                                                   |
| --------------------- | ---------------------------------------------------------------------- |
| 카카오톡              | 장소 링크, 투표, 확정 정보가 채팅 안에 흩어짐                          |
| 네이버지도 / 카카오맵 | 장소 검색과 길찾기는 가능하지만, 그룹 투표와 약속방 관리 기능은 부족함 |
| 캘린더                | 일정 관리는 가능하지만, 장소 후보 선정과 위치 공유 기능은 부족함       |

### 해결 방안

어디가까는 카카오톡을 대체하는 서비스가 아니라, 카카오톡에서 흩어지는 약속 정보를 약속방 단위로 정리하는 서비스이다.

> 카카오톡은 약속을 이야기하는 공간이고, 어디가까는 약속을 결정하고 실행하는 공간이다.

어디가까는 하나의 약속방 안에서 장소 검색, 후보 등록, 투표, 장소 확정, 길찾기, 위치 공유, 도착 상태 확인을 처리한다.

### 기대 효과

- 약속 장소 결정 시간을 줄일 수 있다.
- 여러 장소 후보를 지도 위에서 한 번에 비교할 수 있다.
- 투표 결과와 확정 장소를 쉽게 확인할 수 있다.
- 약속 시간 전 참여자의 도착 상황을 확인할 수 있다.
- 카카오톡에서 흩어지던 약속 정보를 구조화할 수 있다.

## 3. 핵심 기능

### 기능 목록

| #   | 기능명         | 설명                                                        | 우선순위 |
| --- | -------------- | ----------------------------------------------------------- | -------- |
| 1   | 소셜 로그인    | 카카오 또는 구글 소셜 로그인                                | 필수     |
| 2   | 약속방 생성    | 약속 이름, 날짜, 시간, 설명, 선호 지역을 입력해 약속방 생성 | 필수     |
| 3   | 초대 링크 공유 | 생성된 약속방 초대 링크를 복사하거나 카카오톡으로 공유      | 필수     |
| 4   | 약속방 참여    | 초대 링크 접속 후 로그인하여 약속방 참여                    | 필수     |
| 5   | 장소 검색      | Kakao Local API 기반 장소 검색                              | 필수     |

| 7   | 장소 후보 등록 | 검색한 장소를 약속방 후보로 등록                            | 필수     |
| 8   | 장소 투표      | 후보 장소에 1인 1표 투표                                    | 필수     |

| 10  | 길찾기 연결    | 확정 장소를 카카오맵 길찾기 또는 상세 보기로 연결           | 중요     |
| 11  | 위치 공유      | 약속 시간 전 참여자 위치 공유                               | 2차      |
| 12  | 도착 상태 표시 | 도착 근처 / 이동 중 / 미공유 상태 표시                      | 2차      |
| 13  | 캘린더 등록    | Google Calendar URL 방식으로 일정 등록                      | 2차      |

- 영업시간 정보 사용한 필터
- 카카오 맵 평점

### 1. 소셜 로그인

- 설명: 사용자는 카카오 또는 구글 계정으로 로그인한다.
- MVP 기준: 카카오 로그인을 우선 구현한다.
- 구현 방식: OAuth 인증 후 백엔드에서 사용자 정보를 조회하고 JWT를 발급한다.
- 관련 API: `GET /api/auth/kakao`, `GET /api/auth/kakao/callback`

### 2. 약속방 생성

- 설명: 사용자가 약속 이름, 날짜, 시간, 모임 설명, 선호 지역을 입력하면 약속방이 생성된다.
- 생성 후 고유 초대 코드와 초대 링크가 발급된다.
- 구현 방식: 약속방 CRUD API, 초대 코드 생성(UUID 또는 nanoid)
- 관련 API: `POST /api/appointments`, `GET /api/appointments/{id}`

### 3. 초대 링크 공유 및 참여

- 설명: 방장은 초대 링크를 친구들에게 공유하고, 초대받은 사용자는 링크를 통해 약속방에 참여한다.
- 구현 방식: 초대 코드 기반 약속방 조회 및 참여 처리
- 관련 API: `POST /api/appointments/join/{inviteCode}`

### 4. 장소 검색

- 설명: 참여자는 카테고리 또는 키워드로 장소를 검색한다.
- 예시: 강남역 카페, 홍대입구 맛집, 종로 술집
- 구현 방식: 백엔드에서 Kakao Local API 호출 후 필요한 데이터만 프론트엔드에 응답
- 관련 API: `GET /api/places/search`

### 5. 장소 후보 등록

- 설명: 검색 결과 중 마음에 드는 장소를 약속방 후보로 등록한다.
- 후보 정보: 장소명, 주소, 카테고리, 위도, 경도, 카카오 장소 ID, 등록자
- 관련 API: `POST /api/appointments/{id}/candidates`

### 6. 장소 투표

- 설명: 참여자는 등록된 후보 장소 중 하나에 투표한다.
- MVP 기준: 1인 1표
- 구현 방식: 동일 약속방 내 사용자 중복 투표 방지
- 관련 API: `POST /api/appointments/{id}/votes`

### 7. 최종 장소 확정

- 확정 장소는 약속방 상단에 고정되고 지도에 강조 표시된다.
- 관련 API: `POST /api/appointments/{id}/confirm`
- 설명: 방장이 투표 결과를 참고해 최종 장소를 확정한다.

### 8. 위치 공유

- 설명: 약속 시간이 가까워지면 사용자가 직접 위치 공유를 켤 수 있다.
- 구현 방식:
  - Browser Geolocation API로 현재 위치 조회
  - WebSocket/STOMP 기반 위치 공유를 우선 검토
  - 일정 또는 배포 이슈 발생 시 Polling 방식으로 대체
- 위치 공유는 웹페이지에 접속 중일 때만 동작한다.
- 위치 정보는 약속방 참여자에게만 표시한다.
- 최신 위치만 임시 저장하고 약속 종료 후 삭제 또는 만료한다.

## 4. 서비스 흐름 시나리오

1. 사용자가 소셜 로그인으로 접속한다.
2. 약속 이름, 날짜, 시간, 설명을 입력해 약속방을 생성한다.
3. 생성된 초대 링크를 친구들에게 공유한다.
4. 초대받은 사용자는 링크를 열고 로그인 후 약속방에 참여한다.
5. 참여자들은 카테고리 또는 키워드로 장소를 검색한다.
6. 마음에 드는 장소를 약속방 후보로 등록한다.
7. 참여자들은 등록된 후보 장소에 투표한다.
8. 방장은 투표 결과를 참고해 최종 장소를 확정한다.
9. 확정 장소는 약속방 상단에 고정되고 지도에 표시된다.
10. 약속 시간이 가까워지면 사용자는 위치 공유를 켤 수 있다.
11. 참여자들은 지도에서 서로의 위치와 도착 상태를 확인한다.
12. 약속 시간이 지나면 위치 공유는 종료되고 약속방은 기록으로 남는다.

## 5. 차별화 포인트

### 카카오톡과 비교

| 항목           | 카카오톡                  | 어디가까                     |
| -------------- | ------------------------- | ---------------------------- |
| 장소 후보      | 채팅에 링크로 흩어짐      | 후보 목록으로 정리           |
| 투표           | 단순 투표 가능            | 장소 정보/지도와 연결된 투표 |

| 지도 확인      | 링크를 따로 열어야 함     | 지도에서 후보/확정 장소 확인 |

1. 장소 후보를 지도 위에서 한 번에 비교할 수 있다.
2. 투표 결과와 장소 정보를 연결해 보여준다.
3. 확정 장소를 약속방 상단에 고정한다.
4. 약속 시간 전 위치 공유로 도착 상황을 확인할 수 있다.
5. 참여자별 도착 상태를 표시한다.

### 도착 상태 기준

```
확정 장소 기준 100m 이내 → 도착 근처
100m 초과 → 이동 중
위치 미공유 → 미공유
```

## 8. 주요 데이터 흐름

### 로그인 흐름

```
사용자 로그인 요청
→ Kakao OAuth 인증
→ 백엔드에서 사용자 정보 조회
→ 회원 정보 저장 또는 조회
→ JWT 발급
→ 프론트엔드에서 토큰 저장
```

### 약속방 생성 흐름

```
사용자가 약속 정보 입력
→ 약속방 생성 API 요청
→ 초대 코드 생성
→ 약속방 저장
→ 초대 링크 응답
```

### 초대 링크 참여 흐름

```
사용자가 초대 링크 접속
→ 로그인 여부 확인
→ 초대 코드로 약속방 조회
→ 참여자 등록
→ 약속방 상세 화면 이동
```

### 장소 검색 흐름

```
사용자가 장소 검색어 입력
→ 프론트엔드가 백엔드에 검색 요청
→ 백엔드가 Kakao Local API 호출
→ 검색 결과 가공
→ 프론트엔드에 응답
→ 리스트와 지도 마커로 표시
```

### 장소 투표 흐름

```
참여자가 후보 장소 선택
→ 투표 API 요청
→ 약속방 참여자 여부 확인
→ 중복 투표 여부 확인
→ 투표 저장
→ 후보별 투표 수 갱신
```

### 위치 공유 흐름

```
사용자가 위치 공유 ON
→ Browser Geolocation API로 현재 위치 조회
→ WebSocket 또는 Polling 방식으로 서버에 위치 전송
→ 서버가 약속방 참여자 위치 갱신
→ 프론트엔드 지도에 참여자 마커 표시
```

## 2. 배경 및 문제 정의

### 문제

약속을 잡는 과정에서는 다음과 같은 불편함이 발생한다.

- 장소 후보가 채팅방에 흩어져 다시 찾기 어렵다.
- 여러 장소를 지도 위에서 한 번에 비교하기 어렵다.
- 투표 결과와 실제 장소 정보가 연결되어 있지 않다.
- 확정 장소와 약속 시간이 대화 속에 묻히기 쉽다.
- 약속 당일에는 “어디야?”라고 반복해서 확인해야 한다.
- 장소 검색, 의견 조율, 길찾기, 일정 등록이 여러 서비스에 분리되어 있다.

### 기존 도구의 한계

| 기존 도구             | 한계                                                                   |
| --------------------- | ---------------------------------------------------------------------- |
| 카카오톡              | 장소 링크, 투표, 확정 정보가 채팅 안에 흩어짐                          |
| 네이버지도 / 카카오맵 | 장소 검색과 길찾기는 가능하지만, 그룹 투표와 약속방 관리 기능은 부족함 |
| 캘린더                | 일정 관리는 가능하지만, 장소 후보 선정과 위치 공유 기능은 부족함       |

### 해결 방안

어디가까는 카카오톡을 대체하는 서비스가 아니라, 카카오톡에서 흩어지는 약속 정보를 약속방 단위로 정리하는 서비스이다.

> 카카오톡은 약속을 이야기하는 공간이고, 어디가까는 약속을 결정하고 실행하는 공간이다.

어디가까는 하나의 약속방 안에서 장소 검색, 후보 등록, 투표, 장소 확정, 길찾기, 위치 공유, 도착 상태 확인을 처리한다.

### 기대 효과

- 약속 장소 결정 시간을 줄일 수 있다.
- 여러 장소 후보를 지도 위에서 한 번에 비교할 수 있다.
- 투표 결과와 확정 장소를 쉽게 확인할 수 있다.
- 약속 시간 전 참여자의 도착 상황을 확인할 수 있다.
- 카카오톡에서 흩어지던 약속 정보를 구조화할 수 있다.

## 4. 핵심 기능 상세

### 1. 소셜 로그인

- 설명: 약속방 생성자는 카카오 또는 구글 계정으로 로그인한다.
- MVP 기준: 카카오 로그인을 우선 구현한다.
- 구현 방식: 프론트엔드가 카카오 인가 코드를 수신한 뒤 `code`와 `redirectUri`를 백엔드에 전달한다. 백엔드는 카카오 액세스 토큰과 사용자 정보를 조회하고 서비스 JWT를 발급한다.
- 초대 링크로 들어온 사용자는 로그인 없이 게스트 닉네임 입력만으로 제한된 기능을 사용할 수 있다.
- 관련 API: `POST /api/auth/kakao`

### 2. 약속방 생성

- 설명: 사용자가 약속 이름, 날짜, 시간, 모임 설명, 선호 지역을 입력하면 약속방이 생성된다.
- 생성 후 고유 초대 코드와 초대 링크가 발급된다.
- 구현 방식: 약속방 CRUD API, 초대 코드 생성(UUID 또는 nanoid)
- 관련 API: `POST /api/appointments`, `GET /api/appointments/{id}`

### 3. 초대 링크 공유 및 참여

- 설명: 방장은 초대 링크를 친구들에게 공유하고, 초대받은 사용자는 링크를 통해 약속방에 참여한다.
- 로그인 사용자는 계정 기반으로 참여하고, 비로그인 사용자는 게스트 닉네임 입력 후 약속방에 참여할 수 있다.
- 게스트는 약속 정보 확인, 후보 장소 확인, 투표, 길찾기, 선택적 위치 공유를 사용할 수 있다.
- 약속방 생성, 수정, 삭제, 최종 장소 확정, 내 약속 목록 관리는 로그인 사용자에게만 제공한다.
- 구현 방식: 초대 링크 참여 API에서 로그인 사용자 참여 또는 게스트 닉네임 기반 참여를 함께 처리한다.
- 관련 API: `POST /api/appointments/join/{inviteCode}`

### 3-1. 게스트 참여 정책

| 기능             | 로그인 사용자 | 게스트 사용자 |
| ---------------- | ------------- | ------------- |
| 약속방 생성      | 가능          | 불가          |
| 약속방 수정/삭제 | 방장만 가능   | 불가          |
| 초대 링크 참여   | 가능          | 가능          |
| 약속 정보 조회   | 가능          | 가능          |
| 장소 검색        | 가능          | 가능          |
| 장소 후보 등록   | 가능          | 불가          |
| 장소 투표        | 가능          | 가능          |
| 최종 장소 확정   | 방장만 가능   | 불가          |
| 길찾기           | 가능          | 가능          |
| 위치 공유        | 가능          | 가능          |
| 내 약속 목록     | 가능          | 불가          |

게스트 참여는 서비스 진입장벽을 낮추기 위한 기능이다. 단, 중복 투표와 악용을 줄이기 위해 게스트별 임시 토큰을 발급하고 브라우저에 저장한다.

동일 약속방 내 게스트 닉네임 중복은 허용하지 않는다. 중복 닉네임 입력 시 다른 닉네임 입력을 요청하여 투표자와 위치 공유자를 구분하기 쉽게 한다.

게스트는 동일 브라우저에 저장된 `guestToken`으로 재입장한다. 토큰이 없거나 만료된 경우 동일 닉네임으로 새 게스트 참여자로 입장할 수 있으며, 기존 투표 기록은 복구하지 않는다.

초대 링크는 약속방 상태가 `PLANNING` 또는 `CONFIRMED`일 때만 참여할 수 있다. `CLOSED` 상태에서는 신규 참여를 제한하고 약속방 기록 조회만 허용한다.

초대 코드는 충분히 긴 랜덤 문자열로 생성하고, 순차 ID를 노출하지 않는다. 약속방 참여는 초대 코드 검증 후에만 가능하도록 처리한다.

### 3-2. 게스트 참여 처리 방식

게스트 참여는 별도 세션 생성 API를 두지 않고, 초대 링크 참여 API에서 함께 처리한다.

```
POST /api/appointments/join/{inviteCode}
```

요청 예시:

```json
{
  "guestName": "성우"
}
```

응답 예시:

```json
{
  "appointmentId": 1,
  "memberId": 10,
  "memberType": "GUEST",
  "guestToken": "temporary-guest-token"
}
```

프론트엔드는 응답으로 받은 `guestToken`을 브라우저에 저장하고, 이후 게스트 권한이 필요한 요청에 `X-Guest-Token` 헤더로 전달한다.

### 4. 장소 검색

- 설명: 참여자는 카테고리 또는 키워드로 장소를 검색한다.
- 예시: 강남역 카페, 홍대입구 맛집, 종로 술집
- 구현 방식: 백엔드에서 Kakao Local API 호출 후 필요한 데이터만 프론트엔드에 응답
- 관련 API: `GET /api/places/search`

### 5. 장소 후보 등록

- 설명: 검색 결과 중 마음에 드는 장소를 약속방 후보로 등록한다.
- 권한: 로그인 사용자만 장소 후보를 등록할 수 있다.
- 삭제 권한: 후보 등록자 또는 방장만 후보 장소를 삭제할 수 있다.
- 최종 장소 확정 이후에는 후보 장소 삭제를 제한한다.
- 후보 정보: 장소명, 주소, 카테고리, 위도, 경도, 카카오 장소 ID, 등록자
- 관련 API: `POST /api/appointments/{id}/candidates`

### 6. 장소 투표

- 설명: 참여자는 등록된 후보 장소 중 하나에 투표한다.
- MVP 기준: 1인 1표
- 최종 장소 확정 전까지 투표 변경을 허용한다.
- 구현 방식: 동일 약속방 내 참여자 중복 투표 방지
- 관련 API: `POST /api/appointments/{id}/votes`

### 7. 최종 장소 확정

- 설명: 방장이 투표 결과를 참고해 최종 장소를 확정한다.
- 권한: 로그인 사용자 중 약속방 방장만 최종 장소를 확정할 수 있다.
- 게스트는 장소 투표에는 참여할 수 있지만 최종 장소 확정 권한은 갖지 않는다.
- MVP에서는 방장만 최종 장소 확정이 가능하며, 방장 위임 기능은 후순위 기능으로 분류한다.
- 확정 장소는 약속방 상단에 고정되고 지도에 강조 표시된다.
- 관련 API: `POST /api/appointments/{id}/confirm`

### 8. 위치 공유

- 설명: 약속 시간이 가까워지면 사용자가 직접 위치 공유를 켤 수 있다.
- 위치 공유와 도착 상태 표시는 서비스 차별성과 발표 완성도를 높이는 최종 구현 핵심 기능으로 분류한다.
- 기본 약속 흐름을 안정화한 뒤 우선 구현하며, WebSocket 구현이 지연되거나 장애가 발생할 경우 Polling 방식으로 전환해 발표 시나리오를 보장한다.
- 위치 공유는 사용자가 직접 동의하고 ON으로 설정한 경우에만 동작한다.
- 위치 공유 ON 클릭 시 현재 위치가 약속방 참여자에게 표시되며 약속 종료 후 자동 삭제된다는 안내 문구를 제공한다.
- 위치 공유를 원하지 않는 참여자는 위치를 공유하지 않아도 약속방의 다른 기능을 사용할 수 있다.
- 위치 공유는 약속 시간 1시간 전부터 약속 종료 후 30분까지 활성화한다.
- 위치 정보는 약속방 참여자에게만 표시한다.
- 최신 위치만 임시 저장하고 약속 종료 후 삭제 또는 만료한다.
- Geolocation API의 정확도 값이 지나치게 낮은 경우 도착 상태를 확정하지 않고 `위치 확인 중`으로 표시한다.
- 사용자 위치와 확정 장소 간 거리는 Haversine 공식으로 계산한다.
- 구현 방식:
  - Browser Geolocation API로 현재 위치 조회
  - Polling 기반 REST API로 위치 저장, 조회, 권한 검증, Redis TTL, 도착 상태 계산을 먼저 검증
  - 이후 WebSocket/STOMP 기반 실시간 위치 갱신으로 고도화
  - 일정 또는 배포 이슈 발생 시 Polling 방식을 발표 백업 수단으로 유지
- 위치 공유는 웹페이지에 접속 중일 때만 동작한다.

### 8-1. WebSocket/STOMP 적용 전략

팀 내 기존 프로젝트에서 WebSocket/STOMP 구현 경험이 있으므로, 위치 공유의 최종 실시간 통신 방식은 WebSocket/STOMP로 구현한다.

다만 안정적인 개발을 위해 위치 저장, 권한 검증, Redis TTL, 도착 상태 계산은 Polling 기반 REST API로 먼저 검증한다. 이후 동일한 `LocationService`를 WebSocket/STOMP 메시지 처리 로직에서 재사용하여 실시간 위치 갱신으로 고도화한다.

Polling 방식은 WebSocket 구현 지연 또는 배포 환경 이슈 발생 시 발표 백업 수단으로 유지한다.

```
1. LocationService 구현
2. Redis 위치 저장/TTL 구현
3. REST 기반 Polling 위치 전송/조회 구현
4. WebSocket/STOMP 연결 및 구독 구현
5. Nginx/HTTPS 배포 환경에서 WebSocket 검증
6. WebSocket 실패 시 Polling fallback 유지
```

REST Polling API와 WebSocket/STOMP 메시지는 동일한 서비스 로직을 사용한다.

```
REST:
POST /api/appointments/{id}/location
GET /api/appointments/{id}/locations

WebSocket/STOMP:
Send /app/appointments/{id}/location
Subscribe /topic/appointments/{id}/locations
```

### 9. 채팅 기능 제외 및 소통 보완

- 채팅 기능은 MVP 범위에서 제외한다.
- 본 서비스는 카카오톡을 대체하는 채팅 서비스가 아니라, 약속 장소 선정과 진행 상태를 구조화하는 데 목적이 있다.
- 실시간 대화는 기존 메신저를 활용하고, 어디가까는 초대 링크, 장소 후보, 투표, 확정 장소, 위치 공유 상태를 관리한다.
- 채팅이 없어 생길 수 있는 소통 불편은 가벼운 상태 기반 기능으로 보완한다.

| 보완 기능        | 설명                                           | 우선순위 |
| ---------------- | ---------------------------------------------- | -------- |
| 장소 후보 코멘트 | 후보 장소별로 짧은 의견을 남김                 | Could    |
| 방장 공지        | 확정 장소, 시간 변경, 모임 안내를 상단에 고정  | Should   |
| 참여 상태 표시   | 참여자가 도착 예정, 이동 중, 늦음 등을 선택    | Could    |
| 카카오톡 공유    | 상세한 대화가 필요할 때 기존 카카오톡으로 연결 | Should   |

## 5. 서비스 흐름 시나리오

1. 사용자가 소셜 로그인으로 접속한다.
2. 로그인 사용자가 약속 이름, 날짜, 시간, 설명을 입력해 약속방을 생성한다.
3. 생성된 초대 링크를 친구들에게 공유한다.
4. 초대받은 사용자는 링크를 열고 로그인 또는 게스트 닉네임 입력 후 약속방에 참여한다.
5. 참여자들은 카테고리 또는 키워드로 장소를 검색한다.
6. 로그인 사용자는 마음에 드는 장소를 약속방 후보로 등록한다.
7. 게스트를 포함한 참여자들은 등록된 후보 장소에 투표한다.
8. 방장은 투표 결과를 참고해 최종 장소를 확정한다.
9. 확정 장소는 약속방 상단에 고정되고 지도에 표시된다.
10. 약속 시간이 가까워지면 사용자는 위치 공유를 켤 수 있다.
11. 위치 공유를 켠 참여자만 현재 위치가 약속방 지도에 표시된다.
12. 참여자들은 지도에서 서로의 위치와 도착 상태를 확인한다.
13. 약속 시간이 지나면 위치 공유는 종료되고 약속방은 기록으로 남는다.

## 6. 모바일 웹뷰 친화 설계 방향

본 프로젝트는 웹 기반으로 구현하되, 실제 사용 상황이 모바일 중심이라는 점을 고려하여 모바일 웹뷰 친화적인 UI/UX를 우선 설계한다.

1차 MVP는 모바일 웹으로 구현하되, 추후 웹뷰 앱 전환을 고려하여 모바일 우선 UI, HTTPS 기반 배포, 소셜 로그인 리다이렉트 구조, 위치 권한 처리, 외부 앱 연동 방식을 사전에 고려한다.

지도 화면, 장소 후보 목록, 위치 공유 기능은 모바일 터치 환경에 맞춰 구성하며, 추후 PWA 또는 Capacitor 기반 앱 확장이 가능하도록 프론트엔드와 백엔드를 API 기반으로 분리한다.

### 개발 전략

| 단계  | 목표                     | 주요 내용                                                                       |
| ----- | ------------------------ | ------------------------------------------------------------------------------- |
| 1단계 | 모바일 웹 MVP 완성       | 브라우저에서 로그인, 약속방, 장소 검색, 지도, 투표, 위치 공유가 동작하도록 구현 |
| 2단계 | 웹뷰 전환 고려 구조 반영 | 모바일 우선 UI, 명확한 라우팅, 권한 실패 처리, 외부 앱 이동 방식을 정리         |
| 3단계 | HTTPS 기반 실기기 테스트 | 카카오 로그인, 현재 위치 권한, 카카오맵 도메인 설정을 실제 모바일 환경에서 검증 |
| 4단계 | 웹뷰 앱 확장 검토        | 일정 여유가 있을 경우 Capacitor 또는 React Native WebView 기반 앱 래핑 검토     |

### 카카오톡과 비교

| 항목           | 카카오톡                  | 어디가까                     |

4. 약속 시간 전 위치 공유로 도착 상황을 확인할 수 있다.
5. 참여자별 도착 상태를 표시한다.

### 도착 상태 기준


### Redis 사용 전략

Redis는 위치 공유 기능의 최신 위치 저장과 TTL 만료 처리를 위해 사용한다.

| 저장소     | 사용 데이터                                               |
| ---------- | --------------------------------------------------------- |
| PostgreSQL | 사용자, 약속방, 장소 후보, 투표, 최종 장소 등 영구 데이터 |
| Redis      | 참여자별 최신 위치, 위치 공유 상태, 위치 데이터 TTL       |

예시 키:

```
location:appointment:{appointmentId}:member:{memberId}
```

Redis에 저장된 위치 데이터는 약속 종료 후 자동 만료되도록 TTL을 설정한다. 단, 핵심 약속 데이터는 PostgreSQL에 저장한다.

Redis 장애가 발생할 경우 위치 공유 기능은 일시 중단하거나 PostgreSQL 기반 최근 위치 조회로 제한한다. 약속방, 후보 장소, 투표, 최종 장소 확정 등 핵심 기능은 PostgreSQL 기반으로 유지한다.

| Prod        | 발표/운영                 | `https://eodigakka.site`, `https://api.eodigakka.site`         | 필수            |
| 사용자 환경 | 모바일 브라우저 또는 웹뷰 | `https://eodigakka.site`                                       | 필수            |

로컬 개발 환경은 `localhost` 기반 HTTP로 구성한다. 모바일 위치 권한, 소셜 로그인, 카카오맵 도메인 검증은 HTTPS가 적용된 개발 서버에서 진행한다.

Kakao Developers 콘솔에는 localhost, 개발 도메인, 운영 도메인을 각각 등록한다.

### 보안 및 환경 변수 관리

| 항목                 | 관리 기준                                        |
| -------------------- | ------------------------------------------------ |
| Kakao REST API Key   | 백엔드 환경변수로 관리하고 외부에 노출하지 않음  |
| Kakao JavaScript Key | 프론트엔드에서 사용하되 허용 도메인을 제한       |
| Kakao Client Secret  | 백엔드 환경변수로 관리하고 토큰 발급 요청에 사용 |
| JWT Secret           | 백엔드 환경변수로 관리                           |
| DB/Redis 접속 정보   | `.env` 또는 배포 환경 변수로 관리                |
| 개발/운영 키         | Local, Dev, Prod 환경별로 분리                   |

### CORS 정책

백엔드는 허용된 프론트엔드 도메인에서만 API 요청을 허용하도록 CORS를 설정한다.

| ----- | ---------------------------- |

| Dev   | `https://dev.eodigakka.site` |

## 11. 주요 데이터 흐름

### 로그인 흐름

```
사용자가 카카오 로그인 요청
→ Kakao OAuth 인증 및 callback 인가 code 수신
→ 프론트엔드가 code와 redirectUri를 백엔드에 전달
→ 백엔드가 카카오 토큰 API를 호출해 access_token 발급
→ 백엔드가 카카오 사용자 정보 조회
→ 회원 정보 저장 또는 조회
→ 서비스 JWT 발급
→ 프론트엔드가 서비스 JWT로 인증 유지
```

### 약속방 생성 흐름

```
사용자가 약속 정보 입력
→ 약속방 생성 API 요청
→ 초대 코드 생성
→ 약속방 저장
→ 초대 링크 응답
```

### 초대 링크 참여 흐름

```
사용자가 초대 링크 접속
→ 초대 코드로 약속방 조회
→ 로그인 사용자 여부 확인
→ 로그인 사용자면 계정 기반 참여자 등록
→ 비로그인 사용자면 게스트 닉네임 입력
→ 초대 링크 참여 API에서 게스트 임시 토큰 발급 및 참여자 등록
→ 약속방 상세 화면 이동
```

### 장소 검색 흐름

```
사용자가 장소 검색어 입력
→ 프론트엔드가 백엔드에 검색 요청
→ 백엔드가 Kakao Local API 호출
→ 검색 결과 가공
→ 프론트엔드에 응답
→ 리스트와 지도 마커로 표시
```

### 장소 투표 흐름

```
참여자가 후보 장소 선택
→ 투표 API 요청
→ 약속방 참여자 여부 확인
→ 중복 투표 여부 확인
→ 투표 저장
→ 후보별 투표 수 갱신
```

### 위치 공유 흐름

```
사용자가 위치 공유 ON
→ Browser Geolocation API로 현재 위치 조회
→ WebSocket 또는 Polling 방식으로 서버에 위치 전송
→ 서버가 약속방 참여자 위치 갱신
→ 프론트엔드 지도에 참여자 마커 표시
```

## 12. 외부 API 사전 검증 및 실패 대응 전략

프로젝트 시작 전 MVP 핵심 외부 API의 사용 가능 여부를 사전 검증했다.

### 사전 검증 결과

| 기능           | 외부 API                  | 테스트 환경        | 결과 | 확인 내용                                                             |
| -------------- | ------------------------- | ------------------ | ---- | --------------------------------------------------------------------- |
| 카카오 로그인  | Kakao Login               | Mobile HTTPS/ngrok | 성공 | Redirect URI 설정 후 인가 코드 수신 확인                              |
| 장소 검색      | Kakao Local API           | PowerShell/Vite    | 성공 | `강남역 카페` 검색 시 장소 목록과 좌표 응답 확인                      |
| 지도 표시      | Kakao Maps JavaScript API | Mobile HTTPS/ngrok | 성공 | JavaScript SDK 도메인 등록 후 지도 렌더링 및 마커 표시 확인           |
| 카카오톡 공유  | Kakao Share API           | Mobile HTTPS/ngrok | 성공 | 제품 링크 관리 웹 도메인 및 JavaScript SDK 도메인 등록 후 공유창 확인 |
| 현재 위치 조회 | Browser Geolocation API   | Mobile HTTPS/ngrok | 성공 | 모바일 브라우저에서 위치 권한 허용 후 위도/경도 수신 확인             |

### 검증 결론

MVP 핵심 기능에 필요한 외부 API는 테스트 환경에서 정상 동작을 확인했다. 따라서 외부 API 사용 가능 여부로 인해 프로젝트 진행이 중단될 가능성은 낮다고 판단한다.

단, 모바일 위치 조회는 HTTPS 환경과 브라우저/기기 위치 권한이 모두 필요하며, 카카오 API는 현재 접속 도메인에 따라 Redirect URI, JavaScript SDK 도메인, 제품 링크 관리 웹 도메인을 각각 등록해야 한다.

실제 배포 시에는 운영 도메인을 기준으로 아래 설정을 추가한다.

| 설정 항목                  | 운영 설정                                     |
| -------------------------- | --------------------------------------------- |
| 카카오 로그인 Redirect URI | `https://eodigakka.site/oauth/kakao/callback` |
| JavaScript SDK 도메인      | `https://eodigakka.site`                      |
| 제품 링크 관리 웹 도메인   | `https://eodigakka.site`                      |
| 백엔드 CORS 허용 Origin    | `https://eodigakka.site`                      |

### 모바일 테스트 주의 사항

모바일 로컬 테스트에서는 PC IP 기반 HTTP 접속 시 Geolocation API가 제한될 수 있다. 모바일 위치 공유 검증은 HTTPS 환경에서 진행해야 하며, ngrok을 사용할 경우 Kakao Login Redirect URI, JavaScript SDK 도메인, 제품 링크 관리 웹 도메인에 동일한 ngrok HTTPS 주소를 등록해야 한다.

상세 검증 과정은 별도 문서 `eodigakka-external-api-validation.md`에 정리한다.

### 실패 대응 전략

외부 API 의존 기능은 발표 안정성을 위해 대체 흐름을 준비한다.

Kakao API, 위치 권한, WebSocket, 캘린더 연동 등에서 문제가 발생해도 약속방 생성, 장소 후보 등록, 투표, 최종 장소 확정 흐름은 유지되도록 설계한다.

| 기능          | 사용 API/기술             | 실패 시 안전장치                                            |
| ------------- | ------------------------- | ----------------------------------------------------------- |
| 로그인        | Kakao OAuth               | 테스트 계정 또는 개발용 임시 로그인 모드 준비               |
| 게스트 참여   | 초대 코드, 게스트 토큰    | 닉네임 기반 재입장 또는 읽기 전용 약속방 조회 제공          |
| 장소 검색     | Kakao Local API           | 목업 장소 데이터 또는 최근 검색 캐시 사용                   |
| 지도 표시     | Kakao Maps JavaScript API | 장소 후보 리스트 중심 UI로 대체                             |
| 길찾기        | Kakao Map URL             | 주소 복사 버튼 제공                                         |
| 위치 조회     | Browser Geolocation API   | 위치 미공유 상태 표시, 수동 위치 선택 또는 테스트 좌표 모드 |
| 위치 공유     | WebSocket/STOMP           | REST API 기반 Polling 방식으로 전환                         |
| 카카오톡 공유 | Kakao Share API           | 일반 링크 복사 기능으로 대체                                |
| 캘린더 등록   | Calendar URL/API          | 약속 정보 복사 또는 `.ics` 파일 다운로드                    |
| 배포 환경     | AWS                       | 로컬 시연 또는 백업 배포 URL 준비                           |

### 발표 백업 시나리오

- Kakao API 장애 시 사전에 준비한 목업 장소 데이터를 사용한다.
- 위치 권한 실패 시 테스트 좌표 기반으로 위치 공유 흐름을 시연한다.
- WebSocket 연결 실패 시 Polling 또는 수동 갱신 방식으로 대체한다.
- 배포 환경 장애 시 로컬 실행 시연 또는 백업 배포 URL을 사용한다.

## 15. API 명세 초안

> Base URL: `https://api.eodigakka.site/api`
> 인증: 로그인 사용자는 `Authorization: Bearer {accessToken}`, 게스트는 `X-Guest-Token: {guestToken}` 사용

### 공통 에러 응답

```json
{
  "code": "ERROR_CODE",
  "message": "에러 메시지",

}
```

| 상태 코드 | 설명        |

### Auth

카카오 로그인 요청 예시:


## 17. MVP 성공 기준

기본 MVP 성공 기준은 사용자가 약속방을 생성하고, 초대 링크를 통해 로그인 사용자 또는 게스트가 참여한 뒤, 장소 후보를 조회하고 투표를 진행하여 최종 장소를 확정하는 흐름을 완성하는 것이다.

발표 시연 기준은 다음과 같다.

1. 로그인 사용자가 약속방을 생성한다.
2. 초대 링크를 통해 최소 3명의 참여자가 약속방에 입장한다.
3. 로그인 사용자가 장소 후보 3개를 등록한다.
4. 게스트를 포함한 참여자들이 후보 장소에 투표한다.
5. 방장이 투표 결과를 참고해 최종 장소를 확정한다.
6. 확정 장소가 지도에 표시된다.
7. 카카오맵 길찾기 링크로 이동할 수 있다.

최종 구현 성공 기준은 약속 시간 전 참여자가 위치 공유를 ON으로 설정하고, WebSocket/STOMP를 통해 지도에서 참여자 위치와 도착 상태가 실시간으로 갱신되는 흐름을 시연하는 것이다. WebSocket 연결 실패 시 Polling 방식으로 전환하여 동일한 핵심 흐름을 유지한다.

## 24. 테스트 및 시연 전략

### 테스트 기준

핵심 API는 Swagger를 통해 수동 테스트하고, 권한과 중복 처리처럼 오류가 발생하기 쉬운 정책은 단위 테스트 또는 통합 테스트로 검증한다.

| 테스트 대상     | 검증 내용                                          |
| --------------- | -------------------------------------------------- |
| 게스트 참여     | 닉네임 중복 제한, guestToken 발급, 재입장 처리     |
| 장소 후보 등록  | 로그인 사용자만 등록 가능, 게스트 등록 제한        |
| 장소 투표       | 1인 1표, 투표 변경, 중복 투표 방지                 |
| 최종 장소 확정  | 방장만 확정 가능                                   |
| 위치 공유       | 권한 거부, 위치 미공유, Redis TTL 만료             |
| WebSocket/STOMP | 연결, 인증, 송수신, 구독, 재연결, Polling fallback |
| 배포 환경       | HTTPS, WSS, Nginx Upgrade 헤더, CORS 허용 Origin   |
| 외부 API 실패   | 목업 장소 데이터, 링크 복사, 테스트 좌표 모드 대체 |

### 발표 시연 시나리오

1. 방장이 카카오 로그인으로 접속한다.
2. 약속방을 생성하고 초대 링크를 복사한다.
3. 게스트 2명이 초대 링크로 입장한다.
4. 방장이 장소를 검색하고 후보 3개를 등록한다.
5. 게스트를 포함한 참여자들이 후보 장소에 투표한다.
6. 방장이 투표 결과를 참고해 최종 장소를 확정한다.
7. 확정 장소가 지도에 표시되는 것을 확인한다.
8. 카카오맵 길찾기 링크로 이동한다.
9. 위치 공유를 ON으로 설정하고 참여자 위치와 도착 상태를 확인한다.

## 27. 최종 정리

어디가까는 약속 장소를 정하는 과정부터 만나는 순간까지의 흐름을 약속방 안에서 관리하는 모바일 웹 중심 약속 조율 서비스이다.

카카오톡에서 흩어지는 장소 후보, 투표 결과, 확정 장소, 위치 공유 정보를 구조화하여 약속 준비와 도착 확인을 더 편리하게 만드는 것을 목표로 한다.

발표 실패를 막기 위한 최소 완성 기준은 약속방 생성, 장소 검색, 후보 등록, 투표, 최종 장소 확정, 지도 표시, 길찾기 연결이다.

파이널 프로젝트의 최종 구현 목표는 여기에 게스트 참여, 카카오톡 공유, 방장 공지, 위치 공유, 도착 상태, Redis TTL, WebSocket/STOMP 실시간 갱신, Polling fallback, HTTPS/WSS 배포 및 CI/CD를 포함한다. 기능을 단순히 나열하는 데 그치지 않고 로그인부터 약속 실행까지 하나의 사용자 흐름으로 완성한다.
